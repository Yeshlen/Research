# Data Dictionary (generator v1)

Generated by `src/simulate.py` (event log) and `src/features.py` (feature table) from `config/generator.yaml`.

## Files

| File | Rows (20k customers, seed 42) | Contents |
|---|---|---|
| `events_log.csv` | ~2.75M | Raw app events per customer, time ordered |
| `vouchers_truth.csv` | 219,208 | Ground truth per voucher. **Never a model input.** |
| `customers.csv` | 20,000 | What a bank knows: home metro and location, account open date, daily limit at window start |
| `customers_latent.csv` | 20,000 | Hidden simulation parameters (segment, activity rate, typical amount…). For analysing the generator only. |
| `cardless_features.csv` | 219,208 | One row per voucher: stage A + stage B features, label, split |

## Event types (`events_log.csv`)

`login`, `view`, `add_recipient`, `change_limit`, `device_registered`, `password_reset`, `create_voucher`, `redeem_voucher`, `logout`.
`t_min` = minutes since `start_date`. Redemption events carry the voucher's location (`lat`, `lon`) and `channel` (ATM / RETAIL).

## Features (`cardless_features.csv`)

All features are computed from events **before** the moment being scored (streaming replay, no future information).

### Stage A: known at voucher creation

| Feature | Meaning | Why it matters |
|---|---|---|
| `amount` | Voucher amount (R) | Scams push amounts towards the limit |
| `amount_ratio_to_avg_90d` | Amount ÷ customer's average voucher in the last 90 days (1.0 if no history) | Unusual for *this* customer (behavioural profiling) |
| `amount_ratio_to_max` | Amount ÷ largest previous voucher | Larger than anything sent before |
| `amount_to_limit_ratio` | Amount ÷ current daily limit | Scammers drain the full limit |
| `history_count`, `has_history` | Number of earlier vouchers | First-time cardless use is a known red flag; also tells the model how reliable the baseline is |
| `days_since_last_voucher` | Days since previous voucher (365 if none) | Dormant customer suddenly active |
| `vouchers_24h`, `amount_24h`, `vouchers_7d` | Earlier vouchers in rolling windows | Velocity |
| `vouchers_in_session` | Earlier vouchers in the same app session | Split-voucher scams |
| `recipient_known` | Recipient used in an earlier voucher | New beneficiary |
| `is_self_send` | Voucher sent to own number | "Send it to yourself and read me the PIN" scam |
| `recipient_added_in_session` | Recipient added in this session | New beneficiary added under pressure |
| `secs_since_login` | Seconds from login to voucher creation | Rushed or coached sessions |
| `screens_before_create` | App screens viewed before creating the voucher | Coached victims navigate many screens |
| `hour`, `hour_deviation`, `is_night`, `day_of_week`, `is_payday_window` | Timing; deviation from the customer's usual hour | Unusual time for this customer |
| `limit_changed_24h`, `limit_increase_24h` | Limit raised in the last 24h, and by how much | Scammers coach victims to raise limits first |
| `days_since_device_change`, `new_device_7d` | Recent new device | Account takeover / SIM swap overlap |
| `password_reset_7d` | Recent password reset | Credential change before payout |
| `account_age_days` | Account age at creation | New accounts |

### Stage B: known at redemption (only when `redeemed = 1`)

| Feature | Meaning |
|---|---|
| `redeemed` | Voucher cashed out within the window (else expired / pending) |
| `redeem_delay_min` | Minutes from creation to cash-out |
| `redeem_dist_home_km` | Distance of cash-out point from customer's home |
| `redeem_dist_usual_km` | Distance from the centroid of the customer's earlier cash-outs |
| `redeem_hour`, `redeem_is_night` | Time of cash-out |
| `redeem_at_atm` | ATM vs retailer |

### Labels and bookkeeping

| Column | Meaning |
|---|---|
| `is_scam` | 1 if the voucher came from a scam episode |
| `scenario_type` | `normal`, `legit_emergency`, `legit_new_phone`, `legit_travel`, `scam_classic`, `scam_self_send`, `scam_limit_raise`, `scam_split`, `scam_subtle` |
| `episode_id` | Groups vouchers from the same episode (0 for normal) |
| `split` | `train` (created before day 120) or `test` |
| `voucher_id`, `customer_id`, `created_at`, `day` | Identifiers and time |
